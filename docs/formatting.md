# Formatting

Biome formats and lints everything, including the HTML in `.astro` files: `npm run format` writes, and `npm run check` fails on anything unformatted. Zed uses the same Biome through `.zed/settings.json`, which runs `node_modules/.bin/biome` as an external formatter, so no Zed extension is needed.

- **Full `.astro` formatting is experimental** in Biome 2.5: it needs `html.experimentalFullSupportEnabled` and `html.formatter.enabled` in `biome.json`. On an unformatted file it takes two passes to settle, then stays stable.
- **I don't use Prettier.** `prettier-plugin-astro` 1.0.0 puts line breaks inside inline elements, which adds visible whitespace (day 1's redaction highlights overhang their words), and it ignores `htmlWhitespaceSensitivity`.
- **Some lint rules are off on purpose**, scoped in `biome.json` overrides: `a11y/useSemanticElements` on day 1 (its redaction bars are `span role="button"` because a `<button>` can't wrap across lines), `a11y/noNoninteractiveTabindex` on day 2 (the room is a focusable `role="application"` for arrow-key shuffling, which Biome doesn't count as interactive), `a11y/useSemanticElements` and `a11y/useFocusableInteractive` on day 5 (the sheet is an ARIA grid whose cells are reached through `aria-activedescendant`, so they aren't focusable themselves, and a real `<table>` laid out with CSS grid risks losing its table semantics in Safari), `a11y/useFocusableInteractive` on day 6 (Biome misses the `tabindex` on the multi-line knob tags), `a11y/noNoninteractiveTabindex` on day 7 (the dish is a focusable `role="application"`, like day 2's room), `a11y/noRedundantRoles` on the calendar (`role="list"` keeps list semantics in Safari once `list-style` is removed), and `complexity/noImportantStyles` in `.astro` files (the reduced-motion override needs `!important`).
- **SVGs in `src/assets` aren't formatted**, so Illustrator exports drop in untouched.
